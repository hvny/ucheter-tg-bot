# ucheter-tg-bot

Телеграм-бот для учёта личных доходов и расходов.

## Что делает бот

Пользователь ведёт учёт своих финансов прямо в Telegram: добавляет операции (доход/расход) с привязкой к категории, суммой и опциональным комментарием, затем смотрит историю, статистику с графиком и может выгрузить всё в Excel.

Каждый пользователь Telegram видит только свои данные — модель полностью изолирована по `user_id`.

## Модель данных

**Пользователь** — определяется телеграм-id. Регистрируется автоматически при первом обращении к боту (`/start`, но также и любая другая команда сработает, если юзера ещё нет в базе).

**Категория** — принадлежит пользователю, имеет тип (`expense` — расход, `income` — доход) и имя. Категория не удаляется физически: у неё есть флаг `is_archived`. Это сделано, чтобы архивирование категории не ломало историю уже сохранённых по ней операций — они остаются на месте и продолжают её показывать, просто категория больше не предлагается при создании новых операций.

При регистрации нового пользователя ему автоматически создаётся дефолтный набор категорий (продукты, транспорт, жильё, зарплата и т.п.) — чтобы не начинать с пустого списка. Дополнительно пользователь может создавать свои категории — либо заранее через `/categories`, либо прямо на лету во время добавления операции (`/add` → «➕ Новая категория»). Если категория с таким названием и типом у пользователя уже есть (и не архивирована) — используется она, а не создаётся дубликат.

**Операция (транзакция)** — сумма, тип (обязан совпадать с типом выбранной категории), привязка к категории, опциональный комментарий и дата создания. Суммы хранятся всегда положительными; знак (доход/расход) определяется полем `type`, а не знаком числа.

## Команды

| Команда       | Что делает                                                               |
| ------------- | ------------------------------------------------------------------------ |
| `/start`      | Регистрация + приветствие. Создаёт дефолтные категории при первом заходе |
| `/menu`       | Экран с кнопками на все разделы — чтобы не запоминать команды            |
| `/add`        | Пошаговый диалог добавления операции                                     |
| `/categories` | Просмотр категорий, добавление новых, архивирование                      |
| `/history`    | История операций с фильтрами и пагинацией                                |
| `/stats`      | Сводка за период + график по категориям                                  |
| `/export`     | Выгрузка операций в `.xlsx` за период                                    |
| `/cancel`     | Прервать текущий диалог                                                  |

### `/add` — добавление операции

Диалог из пяти шагов, каждый — это редактирование одного и того же сообщения (см. ниже про UI-паттерн):

1. **Тип операции** — расход или доход (инлайн-кнопки).
2. **Категория** — список неархивированных категорий нужного типа + кнопка «➕ Новая категория». Если выбрана «новая» — бот тут же спрашивает название текстом и создаёт категорию с нужным типом.
3. **Сумма** — вводится текстом, принимает и точку, и запятую как разделитель дробной части, валидируется как положительное число.
4. **Комментарий** — текстом или пропустить кнопкой.
5. Операция сохраняется, бот показывает итог: сумма, категория, дата.

На каждом шаге доступна кнопка «❌ Отмена» и команда `/cancel`.

### `/categories` — управление категориями

Показывает список активных категорий, разбитый на расходы/доходы. Из этого экрана можно:

- **добавить категорию** — короткий диалог: тип → название;
- **архивировать категорию** — выбор типа → выбор конкретной категории из списка → архивируется сразу (без отдельного подтверждения), после чего бот показывает обновлённый список.

### `/history` — история операций

Список операций постранично (по 5 на экран), новые сверху. Фильтры применяются независимо друг от друга и не сбрасываются при листании страниц:

- **по типу** — все / только расходы / только доходы;
- **по периоду** — неделя / месяц / всё время (скользящее окно от текущего момента, а не календарный период);
- **по категории** — открывается отдельный экран со списком категорий (учитывает уже выбранный тип).

Вся навигация — это один и тот же экран, который обновляется через `editMessageText`; состояние фильтров и текущая страница закодированы прямо в `callback_data` кнопок, отдельного хранилища состояния диалога не требуется.

### `/stats` — статистика

Показывает сводку за период (доход / расход / баланс) и круговую диаграмму разбивки по категориям для одного из типов (расход или доход — переключается кнопкой). Если по выбранному фильтру нет операций — диаграмма не строится, показывается только текст.

Технически интересный момент: переключение периода/типа должно обновлять уже показанное сообщение, но Telegram не даёт превратить текстовое сообщение в сообщение с фото и наоборот через редактирование — только между двумя фото (`editMessageMedia`). Поэтому логика умеет определять, совместимы ли старое и новое состояние, и либо редактирует медиа на месте, либо удаляет старое сообщение и присылает новое.

### `/export` — выгрузка в Excel

Выбор периода (неделя / месяц / всё время) → бот собирает **все** операции за период (без пагинации) и формирует `.xlsx` со стилизованным заголовком: дата, тип, категория, сумма (расходы — со знаком минус, чтобы сходился баланс при простом суммировании столбца), комментарий.

## UI-паттерн: одно сообщение вместо потока новых

Все многошаговые сценарии (`/add`, добавление/архивирование категории, `/history`, `/stats`, `/export`) работают через редактирование одного сообщения бота, а не через серию новых сообщений — так чат не захламляется. Сообщения, которые присылает сам пользователь в процессе диалога (сумма, комментарий, название категории), бот сразу удаляет после обработки — в чате остаётся только один «живой» экран.

## Стек и запуск

Node.js + TypeScript, grammy (+ `@grammyjs/conversations` для диалогов), PostgreSQL через Drizzle ORM, графики — `chart.js`/`chartjs-node-canvas`, экспорт — `xlsx-js-style`.

```bash
docker compose up -d db   # поднять Postgres
npm run db:push           # применить схему
npm run dev                # запуск в dev-режиме

docker compose up -d       # либо целиком в докере (бот + БД)
```

Подробности по структуре проекта и кодстайлу — в [CLAUDE.md](./CLAUDE.md). Список сделанного и оставшегося — в [TASKS.md](./TASKS.md).

## Валюты и редактирование

При добавлении каждой операции выбери RUB, USD, EUR или RSD. Валюта сохраняется
в операции и отображается в истории и отдельном столбце Excel. Статистика
и график считаются только для выбранной валюты; конвертация не выполняется.

В `/history` нажми кнопку ✏️ нужной операции. Можно изменить сумму, валюту,
тип, категорию и комментарий (в том числе удалить его). При смене типа нужно
выбрать категорию нового типа. Изменения записываются только после «Сохранить»;
«Отмена» или `/cancel` сохраняют исходную запись. Дата операции не меняется.

Перед запуском обновлённого бота примени схему: `npm run db:push`.
Новый столбец `transactions.currency` имеет значение по умолчанию RUB,
поэтому существующие операции остаются рублёвыми.

## Общая статистика и курсы

В `.env` задай `EXCHANGE_API_KEY` из ExchangeRate-API. Курсы загружаются встроенным
`fetch` при запуске, если сохранённый набор отсутствует или истёк, и ежедневно
в 06:00 по `Europe/Belgrade` через `node-cron`. Приложение должно работать в это время.
Для локального запуска отдельный системный cron не нужен.

Перед запуском выполни `npm run db:push`: добавятся таблица `exchange_rates`
(полные наборы курсов относительно USD с датой публикации) и
`users.preferred_currency`. В Docker ключ передаётся через compose.

`/stats` по умолчанию показывает все операции по закреплённым за ними курсам.
Выбор RUB/USD/EUR/RSD в режиме «Все валюты» сохраняет предпочитаемую валюту.
«Одна валюта» показывает исходные суммы без пересчёта.

При создании операция получает `transactions.rate_at` — ссылку на неизменяемый
набор `exchange_rates`. Берётся последний набор не позднее времени операции.
При редактировании суммы, типа, валюты, категории или комментария эта ссылка
и дата операции сохраняются. Последующие обновления API не меняют общий итог
для того же набора операций и той же валюты отображения.

Перед запуском версии с закреплением курсов выполни `npm run db:push`:
добавятся `transactions.rate_at` и `transactions.rate_estimated`.
При запуске и ежедневном обновлении курсов бот автоматически заполняет только
отсутствующие ссылки. Для старых записей берётся последний сохранённый курс
не позднее операции; если такого нет — самый ранний доступный курс.
Если курс опубликован позже операции или уже истёк на момент её создания,
пересчёт отмечается как приблизительный. Загрузка исторических курсов из API
не выполняется: восстановить отсутствующий исторический курс точно нельзя.
Уже закреплённые ссылки не перезаписываются повторным запуском.

Если курсов нет совсем, операция сохраняется без ссылки. Когда курсы появятся,
она получит закреплённый курс по тем же правилам. До этого общий итог для валюты,
требующей пересчёта такой операции, не показывается: вместо частичной суммы
выводятся исходные суммы по валютам. Конвертация в исходную валюту курса не требует.

## Логирование

Pino пишет JSON-события в stdout, ошибки также имеют уровень внутри JSON.
В каждой записи есть ISO-время, уровень и `event`. Обработка Telegram содержит
`updateId`, тип действия (`command.history`, `callback`, `message`) и `durationMs`.
Содержимое сообщений, callback-параметры, суммы, комментарии и токены не записываются.
Ошибки сериализуются только в безопасную категорию, код и HTTP-статус без исходного
текста, SQL, параметров или стека: они могут содержать личные данные и секреты.

Уровень задаётся через `.env`: `LOG_LEVEL=info` по умолчанию, `LOG_LEVEL=debug`
для диагностики. В debug видны ожидаемые ошибки Telegram (например, сообщение
уже удалено или не изменилось), входящие обновления и пропуски обновления курсов.
Неожиданные ошибки UI логируются как warn; сбои обработки, API или БД — error;
ошибки запуска/опроса и необработанные ошибки процесса — fatal.

Для курсов записываются этап (`database.read`, `api.fetch`, `database.write`, `database.pin`),
безопасная причина (например, `invalid-key`, `quota-reached`, `timeout`), дата курса
и длительность. Для локального сохранения можно перенаправить stdout:

```bash
npm run dev >> bot.log 2>&1
```

В Docker: `docker compose logs -f bot`. Автоматическая запись в файлы и ротация
приложением не выполняются; при развёртывании ими управляет окружение.

## Удаление и отмена редактирования

На экране редактирования нет кнопки «Назад в меню». Кнопка «Отмена» и команда
`/cancel` отменяют несохранённые изменения и открывают список всех операций
(все типы, всё время, все категории, первая страница). Это работает и на шагах
ввода суммы, валюты, категории или комментария.

«🗑 Удалить операцию» открывает подтверждение. «Не удалять» возвращает к
редактированию, «Отмена» — к истории. После «Да, удалить» операция физически
удаляется и показывается обновлённый список. Удалённая операция больше не входит
в статистику и экспорт. Удаление ограничено `user_id` текущего пользователя.

## Язык интерфейса

Русский и английский поддерживаются через `@grammyjs/i18n`. Выбор доступен
в меню («🌐 Язык») и командой `/language`, сохраняется в `users.language`.
Переводятся кнопки, диалоги, статистика и заголовки Excel. Названия уже созданных
категорий и комментарии остаются как введены пользователем.

Telegram передаёт параметры боту через `/start`, поэтому ссылки имеют вид:

- русский: https://t.me/HvnyExpenseBot?start=lang_ru
- английский: https://t.me/HvnyExpenseBot?start=lang_en

Если внешняя страница получает `?lang=en`, она должна сформировать ссылку
с `?start=lang_en`. Прямой `?lang=en` в ссылке Telegram бот не получает.
Корректный параметр переключает и сохраняет язык существующего пользователя.
Без параметра используется сохранённый выбор; для нового пользователя — язык
Telegram (английский для `en`, иначе русский). Неизвестный параметр не меняет выбор.
Существующие пользователи после обновления сохраняют русский язык.

При обновлении на VPS сначала примени схему, затем перезапусти бота:

```bash
npm ci
npm run db:push
npm run build
pm2 restart ucheter-tg-bot
```

В последней команде укажи имя своего процесса из `pm2 list`.

## Ежедневная сводка

Открой «🔔 Ежедневная сводка» в меню или `/notifications`. Выбери часовой пояс
по городу (например, `Europe/Belgrade`); выбор включает рассылку. Telegram не
передаёт часовой пояс, поэтому язык и место запуска VPS не используются для
его определения. IANA-пояса учитывают летнее время. При переезде измени пояс
в этих же настройках. По умолчанию рассылка выключена, пока пользователь её
не настроит.

В выбранное время (по умолчанию 20:00) по выбранному поясу бот присылает короткую сводку доходов/расходов
за текущий день с полуночи до момента отправки и столбчатый график сравнения.
Нулевые дни тоже отправляются. Операции после отправки в эту сводку не входят.
Все валюты пересчитываются в предпочитаемую валюту по закреплённым курсам.
Если курсов не хватает, показываются исходные суммы отдельно по валютам.
Сообщение и график используют сохранённый язык пользователя.

«Подробнее» открывает статистику за тот же местный день и до того же момента.
Тип операций, валюта и режим пересчёта переключаются внутри этого окна;
кнопки недели/месяца/всего времени открывают обычные периоды статистики.
Дата, пояс и граница окна хранятся вместе с записью доставки, поэтому ссылка
работает и после полуночи или смены пояса. Сами операции могут быть позже
изменены/удалены — подробная статистика читает их актуальное состояние.
«🔕 Отключить» доступно прямо под сводкой и в настройках. Блокировка бота
(ответ Telegram 403) автоматически выключает рассылку.

Перед запуском примени `npm run db:push`: добавятся `users.time_zone`,
`users.daily_notifications` и таблица `daily_deliveries`. Затем выполни
`npm run build` и перезапусти процесс PM2. Отдельный системный cron не нужен:
встроенный `node-cron` проверяет пользователей каждую минуту. Бот должен работать;
обычная отправка происходит в течение минуты после выбранного времени. При запуске после
этого времени отправляется ещё не отправленная сводка текущего дня, пропущенные дни
задним числом не рассылаются.

Завершённые доставки сохраняются в БД и не повторяются после рестарта.
Для неудачных попыток используются десятиминутная блокировка и максимум три
попытки за местную дату. Неопределённый сетевой результат или остановка между
успешной отправкой в Telegram и записью успеха в БД могут привести к повтору:
Telegram не предоставляет идемпотентный ключ отправки. Запускай один экземпляр
бота в PM2, как требуется для текущего long polling.

### Автоматическое определение пояса на внешней странице

`Intl.DateTimeFormat().resolvedOptions().timeZone` нужно вызвать в браузере
пользователя. В Node.js это был бы пояс сервера. Страница может сформировать
Telegram deep link с языком и поясом, закодированным в base64url:

```js
const lang = new URLSearchParams(location.search).get('lang') === 'en' ? 'en' : 'ru';
const userTimezone = Intl.DateTimeFormat().resolvedOptions().timeZone;
const encodedTimezone = btoa(userTimezone)
  .replaceAll('+', '-')
  .replaceAll('/', '_')
  .replace(/=+$/, '');
const payload = `lang_${lang}_tz_${encodedTimezone}`;
const botLink = `https://t.me/HvnyExpenseBot?start=${payload.length <= 64 ? payload : `lang_${lang}`}`;
// Используй botLink как href кнопки перехода в бот.
```

Бот проверяет и сохраняет IANA-пояс. При первой настройке пояса сводка
включается. Если пользователь уже выключил сводку, повторный переход по ссылке
не включает её заново. Пояс можно сменить вручную в `/notifications`.
Старые ссылки `?start=lang_en` и `?start=lang_ru` продолжают работать.

### Время отправки

В `/notifications` нажми «🕒 Время отправки», выбери час, затем минуты.
Поддерживается любое время от 00:00 до 23:59 с точностью до минуты.
Время сохраняется только при выборе минут; кнопка «Назад» отменяет незавершённый
выбор. Смена времени не включает выключенную рассылку. Значение по умолчанию —
20:00. Перед обновлением примени `npm run db:push`: добавится столбец
`users.notification_time` (число минут от местной полуночи, по умолчанию 1200).

За одну местную дату приходит максимум одна успешно отмеченная сводка:
смена времени после её отправки не создаёт вторую. Если выбранное время уже
