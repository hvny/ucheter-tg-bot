# ucheter-tg-bot

Телеграм-бот для учёта личных доходов и расходов.

Этот README — контекст проекта для AI-ассистента (Claude). Здесь описаны стек, структура, бизнес-логика и договорённости по кодстайлу. Перед началом работы над задачей — свериться с этим файлом.

---

## Стек

- **Runtime**: Node.js + TypeScript
- **Бот-фреймворк**: [grammy](https://grammy.dev/)
- **FSM для диалогов**: `@grammyjs/conversations` (пошаговое добавление операций)
- **БД**: PostgreSQL
- **ORM**: Drizzle ORM (`drizzle-orm` + `drizzle-kit` для миграций)
- **Графики**: `chart.js` + `chartjs-node-canvas` (рендер PNG на сервере, отправка как изображение в чат)
- **Экспорт**: `xlsx-js-style` (выгрузка операций в Excel)
- **Форматирование**: Prettier
- **Запуск в dev**: `nodemon` + `tsx` как исполнитель `.ts`-файлов

## Структура проекта

```
src/
  bot/
    commands/       # хендлеры команд (/start, /add, /history, ...)
    bot.ts          # инициализация grammy Bot, регистрация middleware/команд
  lib/
    constants/      # дефолтные категории, лимиты, тексты кнопок и т.п.
    utils/          # чистые хелперы (форматирование дат, сумм, валидация)
    services/       # бизнес-логика: работа с БД через Drizzle (users, categories, transactions)
  index.ts          # entrypoint, запуск бота
.env                # токены и данные подключения к БД (не коммитить)
drizzle.config.ts   # конфиг drizzle-kit (ожидается, пока не создан)
```

**Принцип разделения**: хендлеры в `bot/commands/` не работают с БД напрямую — они вызывают функции из `lib/services/`. Это позволяет тестировать бизнес-логику отдельно от Telegram API.

## Модель данных (Drizzle, Postgres)

```
users
  id            text (telegram user id), PK
  username      text, nullable   -- telegram username, может отсутствовать
  created_at    timestamp, default now()

categories
  id            serial, PK
  user_id       text, FK -> users.id
  name          text
  type          enum('expense' | 'income')
  is_archived   boolean, default false   -- вместо удаления

transactions
  id            serial, PK
  user_id       text, FK -> users.id
  category_id   integer, FK -> categories.id
  amount        numeric
  type          enum('expense' | 'income')
  comment       text, nullable
  created_at    timestamp, default now()
```

Договорённости:

- Категории **не удаляются** физически, а архивируются (`is_archived = true`), чтобы не ломать историю уже сохранённых транзакций.
- При регистрации нового пользователя создаётся дефолтный набор категорий (см. `lib/constants`).
- `type` у категории и транзакции должен совпадать — при выборе категории для расхода показываются только категории с `type = 'expense'`.

## Команды бота

| Команда       | Назначение                                                                        |
| ------------- | --------------------------------------------------------------------------------- |
| `/start`      | Регистрация пользователя, создание дефолтных категорий, приветствие               |
| `/menu`       | Меню с inline-кнопками: Добавить / Просмотреть / Статистика / Категории / Экспорт |
| `/add`        | Добавить расход или доход (пошаговый диалог через conversations)                  |
| `/history`    | Просмотр операций с пагинацией и фильтрами (тип, категория, период)               |
| `/stats`      | Статистика за период: сводка (доход/расход/баланс) + график (pie/bar)             |
| `/categories` | Просмотр, добавление, архивирование категорий                                     |
| `/export`     | Выгрузка операций в Excel за выбранный период                                     |

`/menu` — основная точка входа, дублирует остальные команды кнопками, чтобы не заставлять пользователя печатать команды вручную.

## Флоу добавления операции (`/add`)

Реализуется через `@grammyjs/conversations`:

1. Выбор типа операции: расход / доход (inline-кнопки)
2. Выбор категории — inline-кнопки из списка неархивированных категорий нужного `type`, плюс кнопка «➕ Новая категория»
   - Если выбрано «Новая категория» — запросить название текстом, создать её сразу с нужным `type`, использовать для текущей операции
3. Ввод суммы текстом — валидация: положительное число, поддержка запятой и точки как разделителя
4. Комментарий — опционально, с кнопкой «Пропустить»
5. Сохранение транзакции с `created_at = now()`
6. Подтверждение пользователю: сумма, категория, дата

**Отмена на любом шаге**: на каждой inline-клавиатуре — кнопка «❌ Отмена» (`callback_data: "cancel"`). Ожидание ввода на каждом шаге проходит через общий хелпер (например, `waitForOrCancel`), который проверяет нажатие отмены и прерывает диалог через `conversation.halt()` с сообщением «Отменено». Дополнительно — команда `/cancel` как текстовый способ выйти из диалога, если пользователь не может/не видит кнопку.

## UI-паттерн: одно сообщение вместо потока новых

Чтобы не засорять чат, весь флоу (`/menu`, `/add`, `/categories` и т.п.) работает через **редактирование одного сообщения**, а не через `delete` + `send` на каждом шаге:

- Первое сообщение диалога отправляется через `ctx.reply(...)`, дальше на каждом шаге вызывается `ctx.editMessageText(...)` (текст + inline-клавиатура)
- ID этого сообщения нужно передавать/хранить в контексте диалога (conversation), чтобы на каждом шаге знать, что редактировать
- Редактирование предпочтительнее delete+send: один запрос к API вместо двух, нет визуального «мигания», не ломается из-за возможных ошибок удаления старых сообщений

**Текстовый ввод пользователя** (сумма, комментарий, название новой категории) бот редактировать не может — это отдельное сообщение юзера. Чтобы чат оставался чистым, такие сообщения удаляются сразу после обработки через `ctx.deleteMessage()` (в личных чатах работает всегда, в группах требует прав администратора у бота — но для этого проекта это не актуально, бот 1:1 с пользователем).

## Кодстайл

- Форматирование — Prettier (`npm run format` / `npm run format:check`)
